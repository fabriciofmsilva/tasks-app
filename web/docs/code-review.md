# Code Review — main

Revisão dos cinco eixos (correctness, readability, architecture, security, performance) sobre o código em `app/`, incluindo o trabalho já commitado na main e as mudanças da sessão atual (race fix em `lib/tasks.ts`, `lib/auth.ts`, `lib/json.ts`, lint fixes).

## Correctness / Security

### 1. (Required) Signup/login sem validação de tipo/presença em `email`/`password`

`app/api/signup/route.ts:5-13`, `app/api/login/route.ts:5-10`

Body não validado além do parse JSON. `POST /api/signup` com `{}` cria user com `email: undefined, password: undefined`. Depois `POST /api/login` com `{}` bate `u.email === undefined && u.password === undefined` → login sem senha. Falha real de auth, testável direto via curl, sem passar pelo form HTML.

**Fix:** validar `typeof email === "string" && typeof password === "string" && email && password` antes de seguir, 400 se falhar. Mesmo padrão já usado em `title` de `api/tasks/route.ts:24`.

### 2. (Required) PATCH `/api/tasks/[id]` persiste `done` sem checar tipo

`app/api/tasks/[id]/route.ts:14-22`

`const { done } = body` vai direto pro `task.done = done` e é gravado no JSON sem checar `typeof done === "boolean"`. Request com `{done: "sim"}` ou `{done: {}}` corrompe o shape do Task no disco — quebra render em `TaskList.tsx:50` (`checked={t.done}`) depois. Mesma classe de bug já corrigida em `title`, ficou faltando aqui.

**Fix:** validar `typeof done === "boolean"` antes de persistir, 400 se falhar.

## Architecture

### 3. (Required) `writeTasks` continua exportado sem chamador externo

`app/lib/tasks.ts:26-28`

Único uso restante é interno, dentro de `updateTasks`. Toda mutação hoje passa pelo lock. Mas `writeTasks` segue exportado — código futuro que importar e chamar direto passa por cima do lock e reintroduz a race condition corrigida nesta sessão.

**Fix:** tirar `export` de `writeTasks`, deixar só `readTasks` (leitura, sem risco) e `updateTasks` (escrita, com lock) públicos.

### 4. (Required) `layout.tsx` ainda aplica classes Tailwind depois do import ter sido removido

`app/layout.tsx:24,26`

Nesta sessão o `@import "tailwindcss"` foi removido de `globals.css` (decisão: não usar boilerplate). Mas `layout.tsx` continua com `className="...h-full antialiased"` no `<html>` e `"min-h-full flex flex-col"` no `<body>`. Antes eram classes quebradas por acidente; agora são definitivamente mortas.

**Fix:** remover as classNames do layout.

## Consider

### 5. Tipo `Task` duplicado

`app/lib/tasks.ts:4` e `app/tasks/TaskList.tsx:7`

Mesma definição `{ id: string; title: string; done: boolean }` em dois arquivos. Exportar de `lib/tasks.ts` e importar em `TaskList.tsx` mataria a duplicação.

### 6. Nenhum teste no repo

Nenhum arquivo `*.test.*`/`*.spec.*` existe. Lock de `updateTasks`, validação de `title`, auth helper — tudo entrou sem teste de regressão. Um teste cobrindo a serialização do lock (duas escritas concorrentes não se pisam) já provaria o fix do race condition.

## Nit

### 7. Metadata do layout ainda é boilerplate

`app/layout.tsx:16-18` — `title`/`description` ainda "Create Next App" / "Generated by create next app", enquanto o resto do app já tem branding próprio ("Task APP").

## Verdict

**Request changes** — itens 1-4 são bugs reais e alcançáveis, não hipotéticos. 5-7 podem entrar depois.
